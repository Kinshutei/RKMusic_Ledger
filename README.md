# RKMusic_Ledger

RK Music の全シンガーの YouTube の数字（再生数・高評価数・コメント数・登録者数）を記録する台帳。
0時に全件、毎時に再生数を取る。記録は一度書いたら書き換えない（取り直し待ちの項目に、正しい値を書き込むときだけ例外）。

## ファイル

| ファイル | 中身 | 書き方 |
|---|---|---|
| `channels.json` | タレント一覧（名前・チャンネルID・並び順） | 手で直すときだけ |
| `flags.json` | 手で決めた種別の例外 `{タレント: {動画ID: 種別}}` | フラグツールで直すときだけ |
| `catalog.json` | 全動画の台帳とチャンネルの情報 | 新着・種別の確定・タイトルの変更があった日だけ書き直す |
| `daily/YYYY/YYYY-MM-DD.json` | 0時の全件 | 書き換えない（取り直し待ちの項目に正しい値を書き込むときと、予備の実行でチャンネルを読み直すときだけ書き直す） |
| `hourly/YYYY-MM-DD/HH.json` | 毎時の再生数 | 書き換えない |
| `pending.json` | 取り直し待ちの一覧（下の「取り直し」） | 0時の回で足し、正しい値が取れたら消す（小さい台帳） |
| `summary/daily_totals.json` | RK全体の日ごとの合計（サイトの「RK全体の再生数」「RK全体の高評価数」のグラフが読む） | 0時の回・予備の実行、取り直しで値が埋まったときに、その日と翌日の分を入れ直す（小さい台帳） |
| `summary/talents/{名前}.json` | シンガーごとの日ごとの合計（サイトのシンガーの Analytics が読む） | 同じく入れ直す（小さい台帳） |

時刻はすべて日本時間。

### summary/daily_totals.json

```
{"dates": [日付], "total": [その日の全チャンネルの総再生数の合計], "inc": {"Movie"|"Short"|"LiveArchive": [その日に増えた再生数]},
 "likes": {"total": [その日の全動画の高評価数の合計], "inc": {"Movie"|"Short"|"LiveArchive": [その日に増えた高評価数]}}}
```

- `inc` は、前の日にもある動画の、増えた分だけを足したもの（サイトの Analytics と同じ数え方）。その日に初めて記録された動画は入らない。最初の日は null
- `likes` も同じ数え方（高評価数が減った動画は足さない）。ただし前の日が「高評価0・コメント0」で、その前の日は高評価が0でない動画（YouTube から一時的に0が返ったもの。2026-11-02 までの記録）は、その前の日の値から数える
- その日か前の日に取り直し待ち（null）の項目があると、合計・増えた数は分からないので null。取り直しで埋まったら入れ直す
- 種別は、計算したときの台帳と例外設定による

### summary/talents/{名前}.json

```
{"dates": [日付], "total": [その日の総再生数], "subs": [その日の登録者数], "inc": {"Movie"|"Short"|"LiveArchive": [その日に増えた再生数]}}
```

- 名前は `channels.json` の名前。数え方は `summary/daily_totals.json` と同じで、全員の `inc` を足すと RK全体の `inc` になる
- 記録を始める前の日は `total`・`subs` が null。`inc` は、その日か前の日にそのシンガーの記録が無ければ null
- 取り直し待ち（null）の項目があるシンガーの日も null。取り直しで埋まったら入れ直す

### catalog.json

```
{
  "channels": {タレント: {"チャンネル名", "banner_url", "uploads"}},
  "videos": {動画ID: {"タレント", "タイトル", "公開日", "duration", "type", "auto", "fixed", "初記録", "外れた日"?}}
}
```

- `type` は例外設定を当てた後の種別（Movie / Short / LiveArchive / Pending）。`auto` は自動判定、`fixed` は自動判定が確定したか
- `外れた日` はチャンネルの一覧から外れた日。その日から収集をやめる。一覧に戻ったら消える

### daily

```
{"date", "at", "channels": {タレント: {"登録者数", "動画数", "総再生数", "取り直し待ち"?}}, "v": {動画ID: [再生数, 高評価数, コメント数]},
 "取り直した時刻"?: {"videos": {動画ID: {項目の番号: 時刻}}, "channels": {タレント: {項目: 時刻}}}, "補完"?: [動画ID]}
```

- `at` は実際に取った時刻
- 値が null の項目は取り直し待ち（下の「取り直し」）。正しい値が取れたら、その値が入り、`取り直した時刻` に取れた時刻が残る（項目の番号は 0 再生数・1 高評価数・2 コメント数）
- 総再生数は、その日のそのチャンネルの動画の再生数の合計。取り直し待ちの再生数があれば null
- チャンネルの `"取り直し待ち": true` は、0時にチャンネルごと取れなかったもの。1:00 の予備の実行で一覧から読み直す
- `補完` は取り切れず、前日の値で埋めた動画（2026-11-02 までの記録）。チャンネルの値を埋めたときは、そのチャンネルに `"補完": true` が付く
- `全体補完: true` は収集が動かなかった日を、直前の daily の値で埋めたもの
- `取り直し` は予備の実行で取り直した時刻
- `移行: "RKMusic_AllSinger_PFR"` は、旧 RKMusic_AllSinger_PFR の記録（history_*.json）から移した日（2026-03-31〜2026-10-17）。
  取った時刻は残っていないので `at` は null。総再生数は、その日の動画の再生数の合計で計算し直した。
  2026-10-18 からは Ledger 自身の記録

### hourly

```
{"date", "hour", "at", "登録者数": {タレント: 登録者数}, "v": {動画ID: 再生数}, "取得失敗"?: [動画ID], "新着"?: [動画ID]}
```

- `v` は前の回から再生数が変わった動画だけ。ある時刻の再生数は、その日の daily に、それより後の hourly を `at` の順に重ねて求める
- `取得失敗` は取れなかった動画。`新着` は台帳にまだ無い動画（次の0時に台帳へ入る）
- 収集が失敗した時間は埋めない（その時間のファイルが無い）

## 取り直し（2026-11-03 から）

0時に取れなかった値を、前日の値などで埋めずに空けておき、正しい値が取れるまで取り直す。

- 取り直し待ちにする項目（再生数・高評価数・コメント数・登録者数・動画数のそれぞれ）
  - エラーで取れなかった項目
  - 「最後に正しく取れた値」が0以外なのに、0で返ってきた項目（記録の上で、0以外から0になって戻らなかった例は無い）
  - 最初から0の項目（待機所の再生数、コメントの付いていない動画など）は、0を正しい値として記録する
- 0時の回で、0で返ってきた項目は5秒後に1回取り直す。それでも直らなければ、値を null にして `pending.json` に入れる
- 毎時の回は全動画の再生数・高評価数・コメント数と全チャンネルの登録者数・動画数を取っているので、その値で取り直し待ちを埋める（取り直しのための呼び出しは無い）。
  前に0以外だった項目は0以外が取れたとき、それ以外の項目は値が取れたときに埋め、その日の daily に値と時刻を書き込み、集計を入れ直す。回数の上限は無い
- 1:00 の予備の実行は、0時にチャンネルごと取れなかったチャンネルを一覧から読み直し、取り直し待ちも同じように取り直す（毎時の回が動かない日のため）
- 一覧から外れた（削除・非公開になった）動画は取り直せないので、取り直しをやめて知らせる（値は空いたまま）

### pending.json

```
{"videos": {日付: {動画ID: {項目の番号: 最後に正しく取れた値}}}, "channels": {日付: {タレント: {項目: 最後に正しく取れた値}}}}
```

- 「最後に正しく取れた値」は、前日の daily の値（前日も取り直し待ちなら、ここに控えた値）。エラーで、前に取れた値が無ければ null

## 通知（GitHub の Issue）

- 「取り直しが続いている項目」: 次の0時の回でも直っていない取り直し待ち。1件の Issue に書き足し、すべて直ったら閉じる
- 「データ収集の欠け 日付」: 0時の一覧が総件数より少ない、初めて見る動画の詳細が取れない、前の日の毎時の記録が無い時間がある、
  毎時の回で前の時間の記録が無い、毎時の回で取れなかった動画のうち削除・非公開と確かめられないもの、など。予備の実行で直ったら閉じる
- 毎時の回で取れなかった動画のうち、ID で取れない（削除・非公開）ものは知らせない。次の0時に「外れた日」が付く

## 収集

`collect.py` を GitHub Actions（`.github/workflows/collect.yml`）で動かす。

- cron-job.org が毎時0分に起動する（`auto`: 0時台は全件、それ以外は毎時）
- 1:00 に予備の実行（`fill`）
- シークレットは `YOUTUBE_API_KEY` だけ
- 収集のときはリポジトリ全体を取り込まず、必要なファイルだけを取り出す
